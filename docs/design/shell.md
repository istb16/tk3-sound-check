# 設計: シェル（トップページとヘッダー）

対象: `src/App.svelte` / `src/pages/Menu.svelte` / `src/shell/`
状態: **実装済み**

## トップページは何か

**ランチャーである。** 開くのは3つの道具をすべて知っているが、使うのは月に数回という人。
だから位置では覚えていない。

したがって最適化するのは「何をする道具か説明すること」ではなく、
**読まずに撃ち分けられること**である。以前のメニューは3枚とも同じ形・同じ色の
カードで、違うのは中の文字だけだった——毎回**読んで**選ばされていた。

ただし `index.html` に Google Analytics が入っており、**これは公開サイト**である。
README は GitHub にしかなく `/` が唯一の着地面なので、初めての人も実際に来ている。

## アイコン

**その道具の画面の縮小図**を描く。一般的な比喩ではない。

| 機能 | 図 | 色 |
|---|---|---|
| 音質チェック | 5軸のレーダーチャート | 青緑 `#006E80` |
| ボリュームチェック | 基準マーカー付きの水平レベルバー | 藍 `#2E4B8F` |
| ハウリングチェック | 1本だけ突出したスペクトル | 琥珀 `#A85400` |

シルエットが五角形／横棒／棘のある山と最大限に違うことが唯一の要件である。
意味が読めることは要件ではない（開く人は3つとも知っている）。

**マイクは描けない**——3つとも全部マイクを使う道具なので、同じ絵が3枚並ぶだけで
見分けの役に立たない。スピーカーも波形も同じ理由で弱い。

**ハウリングに⚠は使わない。** 予兆を出さない・危険と断定しないと決めた道具が
「危険を知らせるアプリ」に見える。

アイコンの実装は手書きのインラインSVG。実行時依存が Svelte だけなので、
アイコンライブラリ・絵文字・画像はいずれも方針と合わない。

## 色

**赤（`--danger`、明るい配色で `#B00020`）は「何かがおかしい」専用**に予約してある——音割れ・発振中・
マイク拒否・計測停止の4つが赤である。だから機能色に赤系は使わない。
`App.test.ts` が色相差で機械的に守っている（警告の赤から35°以上離れていること、
互いに25°以上離れていること、白地で 4.5:1 以上のコントラストがあること）。

琥珀を `#B86000` ではなく `#A85400` にしているのは、前者だと白地でのコントラストが
4.46 で、戻るボタンの文字色として 4.5:1 をわずかに割るためである。

**機能色はメニューのタイルと、機能ページの戻るボタン・タイトル下線まで。**
ページの中身（バー・ボタン・フォーカスリング）には持ち込まない——ハウリングの
突出度バーもボリュームのレベルバーも、閾値を超えると `--accent` から**赤に変わる**
ことで異常を示している。基調色を赤に近づけるほどその変化が読めなくなる。

色が乗るのはアイコンのチップ（角丸の色ベタ）だけで、カードは地の色のまま。

### 共通の土台（tk3 apps）

tk3.biz から公開しているアプリは、見た目の土台をそろえている。土台は
`src/shell/tk-base.css`（tk3 apps 共通の写し。**手を加えない**——直すときは元の写しを
直して写し直す）で、`main.ts` で `app.css` より先に読み込む。

- 土台が持つのは、地・面・文字・線の色（`--tk-*`、明暗とも）、フォント、角丸、影、
  画面の上の `.tk-header` と下の `.tk-footer`。
- `app.css` の `--bg` `--surface` `--surface-alt` `--ink` `--body` `--muted` `--line`
  `--on-ink` は土台の変数の別名にしてある。コンポーネントはこれまでどおり短い名前で書く。
- 土台のアクセント（`--tk-accent`）は SOUND CHECK では `--tk-blue`。ヘッダーのアイコンや
  ブラウザが描くフォーム部品に効く。計測の基調色 `--accent`（青緑）とは別物で、
  バー・ゲージには `--accent` を使う。
- **警告の赤は土台の `--tk-danger` を使わない。** あちらの赤（`#B3261E`）は琥珀寄りで、
  ハウリングチェックの機能色（`#A85400`）との色相差が 35° を割る。
- このアプリにしかない色（採点の `--score-*`、琥珀の箱、VU メーター、機能色の上の字
  `--on-feature`）は `app.css` の変数に置き、必要なら暗い配色の値も同じ場所に持つ。
- パネル（`.panel`）は土台の `.tk-panel` と同じ地・線・角丸・影で、余白だけこのアプリの基準。

### 暗い配色

端末が暗い配色（`prefers-color-scheme: dark`）なら、それに合わせる。切り替えボタンは
置かない。土台と意味が同じ色は `tk-base.css` の側で切り替わる。このアプリにしかない色は
`src/shell/app.css` の `:root` に変数として置き、暗い配色の値は同じ場所の
`@media (prefers-color-scheme: dark)` で差し替える。コンポーネントに色の値を直に
書かない（明暗で切り替わらなくなる）。

明暗どちらでも、文字と地のコントラストは 4.5:1 以上にしている。土台に合わせたときに
足りなかったところは値を直した——補足よりさらに控えめな字（`--faint`）、琥珀の字
（`--amber` と採点の `--score-ok` を `#B86000` から `#A85400` へ。白地で 4.46:1 だった）、
VU メーターの板の上の見出しと目盛りの数字。

- `light-dark()` はまだ使える端末が限られるので使わない。メディアクエリなら古い端末でも効く。
- 音質チェックの採点色も `--score-*` の変数にしてあり、`features/quality/scores.ts` は
  色の値ではなく `var(--score-…)` を返す。
- 機能色（`registry.ts` の `accent`）は暗い地では沈むので、字・枠・下線に使うときは
  `color-mix()` で白に寄せた色（`--feature-ink` / `--tile-ink`）を使う。チップと
  戻るボタンの hover の地は元の色のまま（白い字とのコントラストは上のテストが守っている）。
- 音質チェックの VU メーターは、明るい配色でももともと暗い板なので、明暗で色を変えない
  （`--vu-*`）。板の上の目盛りは、明るい配色の採点色だと暗い板の上で 3:1 を割るので、
  板の中だけ `--score-*` を板の上で読める色（`--vu-good` など）に差し替えている。
  暗い配色では、板と地の境目だけ線で出す。

## ヘッダー

**主役はページによって入れ替わる。**

```
トップページ                        機能ページ

[■] SOUND CHECK          [JA|EN]   [■] SOUND CHECK          [JA|EN]
─────────────────────────────────  ─────────────────────────────────
                                   ┌ ← メニュー ┐
耳では分からないことを、                    音質チェック
その場で数値にする。                          ────
```

画面の上の帯は tk3 apps 共通の `.tk-header`（アイコン＋`SOUND CHECK`、右に言語切替）で、
どのページにも同じ形で置く。看板はこの帯に収め、大きな看板は掲げない。
**トップでは帯の中の看板がページの見出し（h1）**、機能ページでは機能名が見出しになる。

「大きいロゴは押せない」が web の常識なので、**看板を目立たせるほど「押せば戻れる」
は伝わらなくなる**。以前は製品名の1要素に看板と戻る手段の2役を負わせていたが、
役割を分けた。帯の看板も押せばメニューへ戻る（どの tk3 apps でも同じ）が、
それだけに頼らず、機能ページには行き先を書いた戻るボタンを別に置く。

戻るの文言は行き先の名前（`メニュー`）にしている。`SOUND CHECK` は行き先が何なのか
言っていないが「メニュー」は言っており、スマホの左上は最も届きにくい場所なので
短いほうがよい。**画面下には置かない**——測定中の `停止` と的が並ぶと、押し間違えて
ボリュームの基準やハウリングの捕まえた周波数を失う。下だけに置くとスクロールするまで
出口が見えず、直そうとした不満そのものが再発する。

機能ページの見出しは機能名なので、ブランドはタブのタイトル
（`音質チェック | サウンドチェック`）と帯の看板が受け持つ。

画面の下には `.tk-footer` で tk3.biz へのリンクを置く。

看板の綴りは英字固定（`WORDMARK`）である。JA/EN を切り替えるサイトでは、
**翻訳しなくて済む名前のほうが看板に向く**。

## 一行の説明

> 耳では分からないことを、その場で数値にする。
> 会議の録音環境から、会場のPAまで。

主な仕事は説得ではなく**安心**である。名前と3つのボタンしか無い画面は、説明を
省いたのではなく書き忘れたように見える。

誇張しないこと。この製品群は「dBAは原理的に出せません」「点数は判定ではありません」
と言い続けてきた。看板だけ誇張していると信用が落ちる。**手軽さは謳わない**——
ブラウザで動く音声ツールは他にもあり、このサイトが違うのは測っている中身の厳密さで、
手軽さを謳うと一番強い部分を自分で隠すことになる。

## レイアウトの制約

**375×667（iPhone SE）で3枚とも一画面に収まること。**
スクロールしないと選べないランチャーは、いまより遅い。
`App.test.ts` が3枚目の下端を実測して守っている（本番と同じく `tk-base.css` と
`app.css` を読み込んだ状態で測る。読み込まないと帯や余白が本番と違う形で測られる）。

タイルは横長の行で、スマホ1列・PC 3列（`repeat(auto-fit, minmax(280px, 1fr))`）。
**3つは2列に収まらず必ず1枚余る**ので、2列になっていないことをテストで見ている。

余白は body ではなく `App.svelte` の `.page` が持つ（帯とフッターを画面の端から端まで
敷くため）。`main` の幅はページの種類で変える。機能ページは読む幅、メニューだけ全幅
（3枚を1行に並べるため）。中央寄せは flex ではなく `margin-inline: auto` で行う——
body を flex にすると間に挟まる `#app` が中身に合わせて縮み、その中の
`inline-size: 100%` が効かなくなる。

タイルは `<button>` ではなく本物の `<a href>`。公開サイトなので、これだけで
「長押しでリンクをコピー」「新しいタブで開く」が効く。修飾キー付きのクリックは
ブラウザに渡している。

## 幅で判断する、ビューポートで判断しない

`main` の幅はビューポートの 55vw なので、**ビューポート幅で列数を決めると外れる**。
音質チェックの結果は以前 `@media (min-width: 768px)` で2列に割っていたが、
1280px のビューポートでも `main` は 704px しか無く、しかも当時は半分幅の項目の次が
必ず全幅の項目だったため、**右カラムがずっと空**だった。

いまは結果領域にコンテナクエリを張り、**その領域の幅**が 640px を超えたときだけ
2列にしている。対になる相手も付けた（総合点↔判定、レーダー↔内訳）。
1列のときの読む順（総合点 → 判定 → レーダー → 内訳）は変えていない——
判定がこの機能の答えなので、レーダーより先に出す。
