# 設計: ハウリングチェック

ルート: `/howling`　状態: **未実装（メニューに「準備中」で並んでいる）**
前提: [受動リアルタイムモニターの骨格](./realtime-monitor.md)

## この機能が答える問い

**「いま鳴いているのは、どの周波数か。」**

鳴っていること自体は部屋の全員が気づいている。画面を見る必要はない。しかし
**3.2kHz なのか 4.5kHz なのかは、人間の耳では区別できない。** どのフェーダーを、
どのEQバンドを下げればよいのかが分からない。そこを数値にするのがこの道具の全てである。

## やらないこと（意図的に）

- **なきかけ（precursor）の検出はしない。** ループゲインが1に近づいた段階での予兆検出は、
  空調・電源ハム・プロジェクタのファン・歌声の持続音と区別がつかない。この道具は
  「空振りは見落としより重い」（README の既存原則）に従う。空調を指して「危険」と
  言い出したツールは二度と信用されない。**鳴ってから指させばよい。**
- **音を出さない。** 端末の内蔵スピーカーは会議室のPAではないので、能動プローブで
  測れるのは端末自身のマイク–スピーカー間ループだけであり、現場の問題を説明しない。
  さらにAECを切ったまま自分で音を出すと、**ツール自体が本物のハウリングを起こしうる。**
- **履歴もサマリも残さない。** 止めたら何も残らない。
- **点数を出さない。** 刻々変わるものに点数は付かない。

## 出力

**オクターブバンド名を主、周波数を併記。**

```
   発振中
   4kHz 帯 ／ 3.2kHz
```

固定バンドのグライコしか無い現場では「4kHz帯」がそのまま操作になる。
パラメトリックEQがあるなら数値が効く。両方出すコストはほぼゼロ。

バンドは ISO のオクターブ中心周波数を使う:
`63 / 125 / 250 / 500 / 1k / 2k / 4k / 8k`（Hz）

状態は3段:

| 状態 | 意味 |
|---|---|
| 聞いている | 突出した狭帯域ピークが無い |
| 注意 | 突出はあるが持続していない |
| 発振中 | 突出が持続している。周波数を表示する |

## 検出

100ms ごとに `averagePowerSpectrum`（`FFT_SIZE = 2048`）を取り、次の2つを見る。

**1. 突出（狭帯域性）**
スペクトルのピークが、その周辺の中央値に対してどれだけ持ち上がっているか。
ハウリングは1本の細いピークとして立つ。広帯域のノイズでは立たない。

**2. 持続**
同じビン（±1ビン）の突出が 500ms の移動窓で連続しているか。
拍手・咳・机を叩く音は突出するが持続しない。

両方を満たしたときだけ「発振中」にする。**片方だけでは出さない。**

周波数の求め方: 最大ビンとその両隣の3点でパラボラ補間する。
21.5Hz のビン幅より細かい値が出る。

```
δ = 0.5 * (P[k-1] - P[k+1]) / (P[k-1] - 2*P[k] + P[k+1])
f = (k + δ) * sampleRate / fftSize
```

バンド名は `signal.ts` の `bandPowers` ではなく、求めた `f` をオクターブ中心周波数の
表に当てて決める（`bandPowers` は等幅バンドなのでオクターブにならない）。

閾値（突出の dB 差、持続フレーム数）は実装時に合成信号で決める。**採点の閾値とは
無関係に、絶対値で持つ**——README にある通り、採点の尺度と混ぜると採点側を動かした
ときに黙って壊れる。

## 状態機械

```
idle ──(開始)──> listening ──(停止)──> idle
  └──(マイク拒否・失敗)──> error ──(やり直す)──> idle
```

`done` は無い。`analyzing` も無い（聞きながら解析している）。

## 画面

```
[ 状態（大きく） ]
[ バンド名 ／ 周波数 ]
[ オクターブバンドのバー8本。発振中のバンドを強調 ]
[ 停止 ]
```

マイク許可の前は、何をする機能かの説明と開始ボタンだけを出す。

## 検証

真値を注入した合成信号で測る。人手のラベル付けは不要。

- 3.2kHz の正弦波＋ピンクノイズ → 「4kHz帯 / 3.2kHz 付近」を指すこと
- ピンクノイズのみ → 何も指さないこと（空振りしないこと）
- 50Hz/60Hz のハム → 定常的に居るだけなので「発振中」にしないこと
- 拍手のインパルス → 突出しても持続しないので出さないこと
- 歌声（倍音列） → 基音だけを発振と誤認しないこと

音質チェックの検証と同じく `validation/` に置き、適合率と再現率を出す。
**空振りは見落としより重い**という前提で閾値を選ぶ。
