# Grill: メニューとシェルの見た目の刷新
Date: 2026-08-27

## Intent

**月に数回しか開かない人が、読まずに撃ち分けられるランチャーにする。**

トップページは3つの道具のランチャーである。使うのは御社が渡した URL を持つ人で、
3つとも知っているが**毎日は使わない**。だから位置では覚えていない。

不満は3つ同時に出ていた——(1) 地味で作りかけに見える、(2) 押しにくい、
(3) どれがどれか分からない。このうち (3) は「何をする道具か説明が足りない」では
**ない**。既に知っている人なので、正確には「**3枚とも同じ形・同じ色で、毎回読んで
選ばされる**」という見分けの問題である。直し方が変わる（説明的なイラストではなく、
形と色で撃ち分けられること）。

`index.html` に Google Analytics が入っており、**これは公開サイト**である。
README は GitHub にしかなく、`/` が唯一の着地面。初めての人も実際に来ている。

## Constraints

- 実行時依存は Svelte だけ。アイコンライブラリ・絵文字・画像は使わない（手書きの
  インラインSVG）。
- **赤（`#B00020`）は「何かがおかしい」専用**。音割れ・発振中・マイク拒否・計測停止の
  4つが赤なので、機能色に赤系を使わない。
- 誇張しない声を守る。「dBAは原理的に出せません」「点数は判定ではありません」と
  言い続けてきた製品が、看板だけ誇張していると信用が落ちる。
- **iPhone SE（375×667）で3枚とも一画面に収まる**。スクロールしないと選べない
  ランチャーは、いまより遅い。

## Key decisions

- Decision: **メニューの役割は「ランチャー」。説明ではなく見分けを最適化する。**
  Reason: 開く人は3つとも知っている。Alternative considered: 初めての人が
  「これは何のサイトか」を判断する入口として作る案（そちらなら説明的なアイコンと
  長い紹介文が要る）。

- Decision: **アイコンは「その道具の画面の縮小図」。一般的な比喩は使わない。**
  音質＝5角形のレーダーチャート／ボリューム＝基準マーカー付きの水平レベルバー／
  ハウリング＝1本だけ突出したスペクトル。
  Reason: シルエットが最大限に違う（五角形／横棒／棘のある山）ので、月に数回の人でも
  形で当たる。加えて、画面に出るものは全部「測った結果」で装飾ではない、という
  この製品群の原則に合う——アイコン自体が情報になる。
  **マイクのアイコンは使えない**（3つとも全部マイクを使うので見分けの役に立たない）。
  **ハウリングに⚠は使わない**——予兆を出さない・危険と断定しないと決めた道具が
  「危険を知らせるアプリ」に見える。
  Alternative considered: ★・スピーカー・⚠のような一般的な比喩（誰でも読めるが
  輪郭が似る／今回の用途では「誰でも読める」が効かない）。

- Decision: **機能ごとに色を割り当てる。音質＝青緑 `#006E80`（既存accent）／
  ボリューム＝藍／ハウリング＝琥珀。赤系は使わない。**
  Reason: 「地味で作りかけに見える」に最も効くのは色である。形の違いは見分けには
  効くが地味さには効かない。Alternative considered: 単色のまま形だけで撃ち分ける案、
  濃淡と塗り／線で差をつける案（どちらも見分けは解決するが最初の不満が残る）。

- Decision: **機能色はメニューのタイルと、機能ページの戻るボタン／タイトル下線まで。
  ページの中身（バー・ボタン・フォーカスリング）には持ち込まない。**
  Reason: ハウリングの突出度バーは閾値を超えると accent から**赤に変わる**のが
  「いま発振している帯域」を示す唯一の手段である。基調色を琥珀にすると
  琥珀→赤になり、**色相が隣り合うので変化が読めなくなる**。ボリュームのレベルバーも
  同じ構造。ページの基調色を赤に近づけるほど赤の警告が効かなくなる。
  得られるのは「開いた瞬間の色の連想」だけで、その人は自分がどの道具を開いたか
  既に知っている。Alternative considered: ページ全体を機能色にする案。

- Decision: **タイルは横長の行（スマホ1列／PC 3列）。一行説明は残す。**
  Reason: 3つは2列に収まらず、必ず歯抜けになる。正方形タイルには一行説明が入らず、
  月に数回の人には説明がまだ効いている。指の的としても横長のほうが大きい。
  Alternative considered: 正方形タイルの2列グリッド（「タップするUI」の一般的な像）。

- Decision: **アイコンは色のチップ（角丸の色ベタ）に白抜き。カードは白地のまま。**
  Reason: 色の面積を稼ぎつつ、文字は白地の上に残るのでコントラストが落ちない。
  この道具は照明の暗い会場や逆光の窓際で開かれる。カード全体を淡い色地にすると
  そこで効いてくるうえ、薄い色地のカードが3枚並ぶと玩具っぽくなり「厳密に測る道具」
  という中身と食い違う。角丸の色チップに白抜きは「アプリのアイコン」の形そのもので、
  依頼の「タップするUI」に最も近い。Alternative considered: アイコンだけ着色
  （色の面積が足りず最初の不満が残る）、カード全体を淡い色地。

- Decision: **タイルは `<button>` ではなく本物の `<a href>` にする**（`preventDefault`
  して `navigate()` を呼ぶ）。Reason: ルーターは実URLで動き、Firebase の rewrite も
  入っているので、これだけで「長押しでリンクをコピー」「新しいタブで開く」が効く。
  公開サイトでは効く。

- Decision: **サイトの名前は `SOUND CHECK`（英字）。「サウンドチェック」は日本語での読み。**
  Reason: このアプリで最もロゴらしい形をしているのは大文字・字間0.16emの英字のほう。
  JA/EN を切り替えるサイトなので、**翻訳しなくて済む名前のほうが看板に向く**。
  加えて、いまトップには同じ名前が英語（小）と日本語（大）で2回出ており、
  英字をそのまま大きくすると表札が縦に2つ並ぶ。
  Alternative considered: 日本語を名前とする案、二段組でひとつの名前とする案。

- Decision: **説明の一行を入れる。「耳では分からないことを、その場で数値にする。/
  会議の録音環境から、会場のPAまで。」**
  Reason: この一行の主な仕事は説得ではなく**安心**（「作りかけに見える」への答え）で、
  従として初めての人にも効く。この製品群の値打ちは一貫して「人間の感覚では区別
  できないものを分ける」ことにあるので、それをそのまま言えば誇張にならない。
  Alternative considered: 課題提示型（「なんだか音が悪い」を数字に——トラブル
  シューティングの道具に見え、問題が無くても使うボリュームチェックが外れる）、
  手軽さ訴求型（**手軽さは差別化にならない**。ブラウザで動く音声ツールは他にもある。
  違うのは測っている中身の厳密さで、手軽さを謳うと一番強い部分を自分で隠す）。

- Decision: **トップでは `SOUND CHECK` を主役に、機能ページでは機能名を主役にする。
  機能ページから `SOUND CHECK` の表記は消し、左上に `← メニュー` を置く。**
  Reason: 「大きいロゴは押せない」が web の常識なので、**ブランドを目立たせるほど
  押せることが伝わらなくなる**。役割を分ければ両立する。戻るボタンの文言を
  行き先の名前にするのは、`SOUND CHECK` は行き先が何なのか言っていないが
  「メニュー」は言っているから。スマホの左上は最も届きにくい場所なので短いほうが良い。
  ブランドが機能ページから消えることは、タブのタイトル（`音質チェック |
  サウンドチェック`）が補償している。
  Alternative considered: 戻るを画面下に置く案（測定中の `停止` と的が並び、
  押し間違えるとボリュームの基準／ハウリングの捕まえた周波数が消える。中断では
  基準を残す設計にしたのに辻褄が合わない。加えて下だけだとスクロールするまで
  出口が見えず、直そうとした不満そのものが再発する）。

- Decision: **「375×667 で3枚とも一画面に収まる」を Playwright のテストで機械的に守る。**
  Reason: このプロジェクトは推定精度も文言も全部テストで守ってきた。レイアウトの
  制約だけ「気をつける」で運用すると、次に余白を触った瞬間に黙って壊れる。
  Alternative considered: 看板の見栄えを優先し3枚目は隠れてもよいとする案
  （スクロールを促す設計はランディングページの手法で、ランチャーには要らない）。

## Surfaced assumptions

- 「タイル形式にして」と言われたが、**メニューは既にタイル**である（全幅のカードが
  縦に3枚）。足りないのはタイルではなく、色・アイコン・面積・押した感触だった。
- 「SOUND CHECK を目立たせたい」という要望そのものが、**見せる相手がいる**ことの
  証拠になっている。純粋なランチャーに自分の名前を大きく掲げる理由は無い
  （開いた本人はどのサイトを開いたか知っている）。
- 依頼の後半には「ブランドを立てたい」と「戻れることを分からせたい」という
  **別々の2つの要求**が入っていた。機能ページ上ではこの2つは正面から衝突する。
- タイルの一行説明は、月に数回の人にはまだ効いている。名前だけで
  「ボリュームチェックはPA調整用、音質チェックは録音判定用」を思い出せるとは限らない。

## Out of scope

- 機能ページの中身（バー・ボタン・レイアウト）の色と構成。触るのは戻るボタンと
  タイトル周りだけ。
- ページ全体を機能色で塗り分けること。
- 正方形タイルの2列グリッド。
- 4つ目以降の機能を見越したレイアウト（3つ前提で組む）。
